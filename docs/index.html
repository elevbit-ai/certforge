CertForge

Autoridade Certificadora que emite certificados de cliente para autenticar conexões com Oracle Database e Azure SQL. Sem o certificado, a conexão não acontece.

Como funciona

O certificado é a metade pública de um par de chaves, assinada por uma autoridade em quem o servidor confia. Quem prova a identidade é a chave privada, que fica só com o cliente.

CLIENTE SERVIDOR (Oracle / Azure SQL) 1. "Quero conectar" ─────────▶ ◀───────── 2. "Me mostre um certificado assinado por uma CA que eu confio" 3. Envia o certificado + prova a chave privada ─────────▶ 4. Verifica: assinado pela minha CA? não revogado (CRL)? chave confere? ◀───────── 5. ✅ aceita ou ❌ recusa

Se o cliente não apresenta um certificado válido — ou tem o certificado mas não a chave privada — a conexão é recusada no handshake TLS, antes de chegar em usuário e senha.

Recursos de segurança diferenciados

Boas práticas comprovadas combinadas num sistema coeso — sem reinventar criptografia.

1

Ledger à prova de adulteração

Cada evento carrega o hash SHA-256 do anterior. Alterar o histórico quebra a cadeia inteira — e o sistema aponta a linha fraudada.

2

Chave selada ao TPM

No Windows, a chave privada é importada como não-exportável e movida para o TPM 2.0. Nem um admin consegue copiá-la.

3

Menor privilégio

Certificados saem com EKU = clientAuth apenas. Se vazarem, não forjam servidor, código ou e-mail.

4

Raiz offline

A raiz assina só a intermediária (pathlen:0) e fica offline. O dia a dia usa a emissora, de curta duração.

5

Revogação com CRL

Cada certificado embute o ponto de distribuição da CRL. Revogou? O servidor recusa na próxima leitura.

6

Chaves cifradas (AES-256)

As chaves das CAs ficam cifradas em repouso, com validação de força da passphrase.

Instalação

O instalador confere os requisitos, importa o módulo e roda um teste de ponta a ponta na sua máquina.

git clone https://github.com/elevbit-ai/certforge.git
cd certforge
pwsh ./scripts/install.ps1

Uso rápido

1 · Criar a Autoridade Certificadora

pwsh ./scripts/new-ca.ps1 -Store ./minha-pki
⚠️ Ao final, mova minha-pki/root-ca/private/root-ca.key.pem para armazenamento offline. É a chave mais valiosa da sua PKI.

2 · Emitir para Oracle

pwsh ./scripts/issue-client.ps1 -CommonName "svc-etl" -Upn "svc-etl@empresa.com" `
    -Store ./minha-pki -Oracle -DbHost "db.empresa.com" -ServiceName "ORCLPDB1"

3 · Emitir para Azure SQL

pwsh ./scripts/issue-client.ps1 -CommonName "svc-bi" -Upn "svc-bi@empresa.com" `
    -Store ./minha-pki -AzureSql -SqlServer "srv.database.windows.net" -Database "vendas"

4 · Guardar a chave selada ao TPM (Windows)

pwsh ./scripts/issue-client.ps1 -CommonName "svc-seguro" -Store ./minha-pki `
    -ImportToWindows -BindToTpm
